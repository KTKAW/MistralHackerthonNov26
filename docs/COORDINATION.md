# Parallel build coordination — 3 tracks, 3 humans, 3 Mistral subscriptions

Base branch: **`build/base`** — contains the shared contract (`.gitignore`, `schema/`,
`examples/`), the master plan (`docs/build-prompt.md`), this file, and the three track prompts.
Each human checks out ONE track branch and runs ONE agent with their OWN `MISTRAL_API_KEY`.

| Track | Branch | Prompt file | Owns | Human |
|---|---|---|---|---|
| A — sandbox & per-repo worker | `build/track-a-sandbox-worker` | `docs/prompts/track-a-sandbox-worker.md` | `sandbox/`, `worker/`, `vibe-home/` (gitignored) | 1 |
| B — demo fleet & wheelhouse | `build/track-b-fleet` | `docs/prompts/track-b-fleet.md` | `fleet/` (`wheelhouse/` is gitignored, built locally per machine) | 2 |
| C — orchestrator, gate, report, web | `build/track-c-orchestration-ui` | `docs/prompts/track-c-orchestration-ui.md` | `orchestrator/`, `web/`, `docs/BUILD-LOG.md` | 3 |

## Launch — one per human, own key, own branch

```sh
# Human 1 (track A)
git checkout build/track-a-sandbox-worker
export MISTRAL_API_KEY=sk-...   # YOUR OWN subscription key
export OTEL_ENABLED=false
vibe --prompt-file docs/prompts/track-a-sandbox-worker.md --workdir . --trust --auto-approve --model mistral-large-4-0

# Human 2 (track B — no model calls needed, hand verification only)
git checkout build/track-b-fleet
vibe --prompt-file docs/prompts/track-b-fleet.md --workdir . --trust --auto-approve --model mistral-large-4-0

# Human 3 (track C)
git checkout build/track-c-orchestration-ui
export MISTRAL_API_KEY=sk-...   # YOUR OWN subscription key
export OTEL_ENABLED=false
uv add mistralai-workflows fastapi uvicorn
vibe --prompt-file docs/prompts/track-c-orchestration-ui.md --workdir . --trust --auto-approve --model mistral-large-4-0
```

Each subscription is billed separately and has its own rate limit, so the three build agents —
and later the per-repo fan-out — never share one quota. (Evidence from 21 Nov: 3 parallel
activities on a single key, zero rate-limit errors; 10 at once is still untested.)

## Rules for all tracks

- Edit ONLY the files your track owns — this is what keeps the branches mergeable.
- Never commit `.env`, `vibe-home/`, `runs/`, `wheelhouse/`. Keys live only in your own shell
  env or your own `vibe-home/.env`.
- Scope rules: proof tests only against our own demo code, isolated; publicly known flaws only;
  harmless proof inputs only (forged request accepted / empty marker file); never auto-post to
  third-party trackers; the tool never sends anything to ENISA — a human submits.
- "Not affected" is worded "no reachable path found", never "safe".
- Vibe pinned to 3.1.3; macOS `sandbox-exec` only; `OTEL_ENABLED=false` everywhere.
- Commit after each step, always with:

```sh
git commit -m "<message>"

Generated by Mistral Vibe.
Co-Authored-By: Mistral Vibe <vibe@mistral.ai>
```

## Merge order

1. Tracks A and B merge into `build/base` first, in either order:
   `git checkout build/base && git merge --no-ff build/track-a-sandbox-worker`
2. Track C rebases/merges LAST (it consumes A's `run_repo` and B's `fleet`):
   `git checkout build/base && git merge --no-ff build/track-c-orchestration-ui`
3. Push to the shared remote only if the team has agreed to use it.

(`web/app.py` + demo rehearsal), both against the pinned contracts above.
